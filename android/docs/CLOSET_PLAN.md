# 옷장 이식 계획

범위: 옷장 검색·상하의/세부 카테고리 필터 → 등록 방식 선택 → 직접 입력/상품 링크/사진 OCR → 서버 원자적 저장 → 상세/이름/사진/삭제 → 홈 기준 의류 갱신.

1. 완료: SwiftUI 화면/서버 계약 대조. 기존 branch codex/android-native-port 유지.
2. 완료: 실제 API 저장소/계정 범위 상태 및 Compose 화면, Android 사진/OCR/crop.
3. 완료: wire/state/OCR 검사, 기기 시나리오 및 iOS 원본 비교, 제한 기록. 최신 36개 캡처의 CJK 검토, 8개 원본 화면 비교, 기능·코드 검토 통과. 네이티브 렌더링 차이와 실제 서버 쓰기 미검증 범위는 CLOSET_VALIDATION.md에 기록.

변경 경계 android/만. 유효하지 않은 숫자를 원본의 기본값으로 대체하거나 원본의 임의 점수를 실제 분석 점수로 표시하지 않는다. 사진 영구 업로드 서버 계약은 없어 원본처럼 세션 내 사진을 사용한다. 기준 의류/비교점수는 서버 응답만 사용한다. 실제 사용자 옷을 임의 생성·삭제하지 않고 개발용 서버 fixture로 쓰기 시나리오를 검증한다.
