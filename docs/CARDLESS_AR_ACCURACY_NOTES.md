# AR 실측 안정성 및 좌표 보정 검증 (2026-10-27)

최우선은 올바른 랜드마크와 AR cm 정확성이다. 기존 `codex/camera-auto-guides`에서 수정했으며 Phase 3는 변경하지 않았다. 아래 결과는 개발 검증이고 운영 활성화 승인이 아니다.

## 실측 경로의 변경

- iOS/Android의 AR 준비 조건에서 매 프레임 이동 거리를 더하던 방식을 최초 위치 대비 최대 실제 이동 거리로 바꿨다. 수정 전 iOS 런타임 테스트에서는 **1 mm 왕복 흔들림만으로 9.9 cm 이동했다고 판정**해 촬영 준비가 완료됐다. 같은 입력을 새 회귀 테스트에서 거부한다. 최소 3 cm 이동·1초 평면 안정·0.3초 정지 조건은 유지한다.
- 카메라 전방 축만 비교하던 정지 판정을 전체 회전과 시간당 각속도로 바꿨다. 롤 회전과 프레임률 10/30/60 Hz에서 계속 회전하는 입력을 거부한다. 정지 기준은 이동속도 0.03 m/s 미만, 각속도 0.04 rad/s 미만이며 실제 기기에서 검증·조정이 필요하다. 이 기준을 cm 오차 보장으로 해석하지 않는다.
- 과거 타임스탬프는 안정 상태를 초기화하고 같은 프레임은 동일한 카메라 상태에서만 재사용한다. 카메라가 아래쪽을 향해야 하며 천장을 향한 포즈를 수직 촬영으로 허용하지 않는다.
- iOS는 촬영 버퍼 크기와 원본 카메라 해상도가 일치해야 한다. Android는 CPU 이미지의 센서 타임스탬프를 `Frame.androidCameraTimestamp`와 비교하고, 전체 이미지 크롭·원본 내부 파라미터 크기도 일치해야 촬영한다. Android의 일반 AR 프레임 타임스탬프와 카메라 센서 타임스탬프를 같은 시계라고 가정하지 않는다.
- 기존 frozen-frame 내부 파라미터·포즈·평면 경계와 실제 3D 평면 거리 계산은 유지한다. AI 처리 중 현재 카메라 포즈로 과거 사진을 재해석하지 않는다. 불안정하거나 경계 밖인 측정은 거부한다.
- iOS 확대 사진의 측정점/카드 보정은 고정된 뷰포트 좌표에서 이동량을 환산한다. 측정점은 화면상 크기를 유지하며, 점을 끌 때 사진도 함께 이동하지 않는다. 배경 팬은 확대 상태에서만 활성화한다. 최초 수정에서 발견한 기본 배율의 스크롤 회귀를 해결하고 기존 사이즈 선택·리포트·차감 테스트를 다시 통과시켰다.

카드/LiDAR raw value와 저장·사진·FitLab·차감 경로는 유지했다. 새 기능 플래그는 전부 false이며 기존 `CoorditCameraComparisonEnabled`도 활성화하지 않았다. 운영 DB/RLS/RPC는 수정하지 않았다.

## 검증 결과: 수학과 실제 센서 정확도의 구분

높이 0.65/1.1/1.8 m, 기울기 0/0.25/0.5 rad, 사진 방향 4종에서 알려진 실제 길이의 점을 독립적인 정방향 투영식으로 만든 뒤 역투영을 검증했다. iOS에서 시야에 들어오는 **168개 수학적 케이스**의 최대 수치 오차는 약 **0.000018 cm**였다. Android에도 같은 방식의 기하 테스트를 추가했다. 이는 좌표식의 수치 검증이며 **실제 AR 센서 MAE가 아니다**. 결과는 `ml/reports/ar-mathematical-geometry.json`에 구분해 기록했다.

최종 증거 위치는 `/tmp/coordit-real-data-evidence/`이다. 이 로컬 임시 경로는 영구 아티팩트 저장소가 아니며 아래 결과 요약과 버전 정보만 Git에 보관한다.
