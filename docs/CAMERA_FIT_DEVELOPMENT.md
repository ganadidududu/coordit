# Camera Fit 개발 상태

## 2026-10-27 고정 가이드 제거와 탭 보정

- 고정 의류 실루엣과 카드 배치 영역을 제거했다. Core Motion의 중력·회전·가속도로 수직 촬영/흔들림/촬영 가능 안내를 표시하고, 4개 연속 샘플로 문구 깜박임을 줄인다. 센서가 없는 시뮬레이터에서는 일반 촬영 안내만 표시한다.
- 사진을 넣으면 자동으로 카드와 옷을 찾는다. 카드 후보가 여러 개면 사진에서 카드를 눌러 선택한다. 카드/옷 버튼으로 다시 찾을 대상을 선택할 수도 있다. 실패한 재인식은 기존 측정값을 삭제하지 않는다.
- 카드 모서리와 옷 측정점을 끌어 보정할 수 있다. 카드 보정은 기존 옷 측정점의 사진 좌표를 유지하면서 cm를 재계산한다. 직접 지정 메뉴는 인식 실패 시 사용할 수 있고, 세로로 놓인 카드도 긴 변을 기준으로 보정한다.
- 작은 회전 카드에서 나타난 약 3cm 오차를 재현하고 윤곽 해상도를 1024에서 2048로 높였다. 5개 카드 위치/회전 합성 사례, 기존 11개 의류 품목, 복수 카드 탭 선택과 보정 회귀 검사를 추가했다. 합성 사례의 허용 오차 통과는 실물 cm 정확도 보장이 아니다.
- 공개 aRTF Clothes 데이터의 8개 장소 × 티셔츠/반바지 16장을 테스트 번들에 추가했다. 파일별 출처와 CC BY 4.0 고지는 `coordit/coorditTests/CameraDataset/ATTRIBUTION.md`에 있다. 앱 번들에는 포함되지 않는다. 파일명 정렬상 각 장소의 첫 사진을 선택했으며, 학습은 수행하지 않았다.
- 실제 사진의 근사 윤곽 IoU ≥ 0.5는 초기 6/16에서 작은 윤곽 허용 후 7/16이다. cm 실측과 카드가 없는 자료이므로 측정 정확도 평가는 아니다. 현재 개발 표본에서 알고리즘을 수정했으므로 독립 테스트 정확도도 아니다. 측정점 제안은 3/16에서 나왔지만 봉제선 정답과의 정확도는 아직 평가하지 않았다.
- Apple 전경 분리 모델을 실패 시 보조 경로로 추가했다. iOS 26.5 시뮬레이터에서 Vision Code 9 (`Could not create inference context`)가 발생해 해당 모델의 개선 효과는 검증하지 못했다. 이 경우 기존 윤곽 검출과 탭/직접 보정으로 진행한다. 실기기에서 모델과 기울기 안내를 확인해야 한다.
- `/tmp/coordit-camera-tap-final-unit.xcresult`에서 단위 검사 42개, `/tmp/coordit-camera-tap-verified.xcresult`에서 UI 시나리오 4개가 통과했다. UI 시나리오는 링크→측정→리포트, 세 품목 촬영→옷장, 큰 글자/취소, 복수 카드 사진→카드 탭→모서리 드래그→옷장 저장이다. Debug 실행과 unsigned Release 기기용 빌드도 통과했고 Release 기능 플래그는 false다.

## 사용자 흐름

상품 링크·사이즈표 사진 → 내 옷 촬영(또는 내 옷 링크) → 측정선 보정·확인 → 사진·AR 비교와 상세 리포트다. 정상 링크의 사이즈표 검토 및 확인 완료 화면을 건너뛴다. OCR도 신뢰도 0.85 이상이고 네 치수가 정상 범위이면 자동 진행한다. 잘못되거나 누락된 값만 편집으로 보낸다. 상품 사이즈표는 접힌 상태로 제공하고, 상품 정보 수정은 보조 동작이다.

촬영 품목은 앱의 기존 11개 세부 품목(티셔츠·셔츠·스웨트셔츠·후드·니트·재킷·코트·팬츠·데님·반바지·스커트)을 공유한다. 상의는 어깨·가슴 단면·총장·소매, 바지는 허리·엉덩이 단면·밑위·아웃심을 제안하며 스커트에는 밑위를 만들지 않는다. 품목은 사용자가 고르고, Vision의 카드 사각형 및 윤곽 검출과 실루엣 규칙으로 측정선을 제안한다. 이는 학습된 품목·봉제선 분류 모델이 아니다. 뒤집힘·가림·구김·복잡한 배경·래글런 소매에서는 재촬영이나 점 지정이 필요하다. 사진 위 점을 끌어 보정하고 마지막 비교 버튼으로 확인한다.

카드는 옷과 같은 평면에 두며 화면 속 위치는 제한하지 않는다. 카메라에는 기울기·움직임 안내만 표시한다. 사진 선택과 촬영은 같은 자동 검출 경로를 사용하며 추정 치수는 사진 위에 바로 표시한다. 카드 비율은 이미지 픽셀 기준으로 검증하고 충분한 해상도가 없는 카드는 보정 검사에서 거부한다. DEBUG 시뮬레이터의 UI 테스트 모드만 촬영 미리보기와 합성 사진을 사용하며 실제 기기는 카메라 사진을 사용한다.

- LiDAR: 사진 윤곽의 측정점 후보를 ARKit 수평면 raycast에 연결한다. 처리 도중 카메라가 이동하면 결과를 거부한다. depth confidence와 같은 평면 조건을 확인하며 자동 실패 시 8개 끝점을 지정할 수 있다. 실기기 검증 전이다.
- 일반 카메라: 표준 신용·체크카드 크기(85.60 × 53.98 mm)의 카드와 옷을 같은 평면에서 촬영한다. 카드의 직선 변을 피팅해 둥근 모서리 오차를 줄인 뒤 원근 보정한다. 여러 카드 후보가 있으면 자동 선택하지 않는다. 카드 문자를 OCR하지 않으며 사진은 확대·이동할 수 있다.
- 실제 사진 또는 실시간 AR 영상 위에 내 옷의 점선과 상품 치수의 실선을 겹친다. 상품 사진을 변형한 가상 착용 이미지가 아니라 부위별 길이·너비 비교다. 사이즈 선택 시 같은 기준선에서 치수가 변경된다.
- 옷장 등록은 내 옷 촬영·링크·사이즈표 사진을 제공하며, 카드 아래 작은 직접 입력 버튼도 쓸 수 있다. 사이즈표 사진은 표 영역을 잘라 기기에서 인식한 뒤 내 사이즈를 골라 저장한다. 핏 랩과 옷장은 같은 입력 카드·패널·보조 버튼 컴포넌트를 사용하며 사이즈표 사진 등록의 버튼·안내 문구도 공유한다. 촬영 치수는 기존 의류 저장 API로 저장하며 원본 사진을 전송하지 않는다. 핏 랩의 내 옷 링크 등록은 저장 후 선택 상태를 유지한 채 핏 랩으로 돌아온다.
- 상의·하의와 세부 품목은 공통 `CoorditGarmentCategorySelector`로 선택한다. 화면에는 현재 품목을 표시하는 전체 너비 버튼을 두고, 누르면 체크 표시가 있는 하단 목록을 연다. 핏 랩 링크·직접 입력·OCR 보완 및 옷장 등록이 같은 컴포넌트를 사용한다. 링크 화면은 링크 입력 다음에 옷 종류를 배치한다. 옷장 등록 방식 화면의 제목에는 상단 페이드 마스크를 적용하지 않는다.
- 비교 화면에는 기존 세부 품목 전체에서 `촬영해서 비교`와 `옷장에서 골라 비교`를 함께 표시한다. 저장된 옷을 선택해도 촬영 진입 버튼은 유지하며, 옷장 목록을 접었다 펴도 선택을 보존한다. 촬영으로 비교가 완료되면 선택한 품목·사진·치수의 옷장 저장 완료를 표시한다.
- 예시 체험은 핏 랩 진입 화면과 옷장 메인·등록 방식 화면의 상단 사용법에 통합했다. 공통 안내 창은 촬영 → 측정점 확인 → 사진·치수 저장 흐름을 설명하고, 촬영이 어려울 때 링크를 쓰도록 안내한다. `링크 예시로 따라하기`는 별도 예시 데이터를 사용해 차감·저장 없이 진행한다. 핏 랩 예시도 정상 사이즈표의 검토·확인 완료 화면을 건너뛴다. 사용법을 닫으면 입력 상태를 유지한다.
- 측정 화면에는 카메라 추정치임을 표시한다. 부위별 측정 기준이 다른 사이즈표는 사용자가 먼저 확인해야 한다.
- 최종 측정 확인 시 카드 촬영 사진 또는 LiDAR 화면의 스냅샷을 옷장 사진으로 자동 반영한다. 측정선 UI를 제외한 최대 1200px JPEG를 계정·의류별 Application Support 파일로 보관하며, 같은 기기에서 재시작 후 옷장을 불러올 때 복원한다. 핏 랩에서 자동 등록한 기준 옷에도 적용한다. 사진 교체·의류 삭제·계정 삭제 시 해당 파일도 갱신·삭제한다. 서버 업로드와 다른 기기 사진 동기화는 포함하지 않는다. 측정 세션의 카드 보정값·AR 공간 상태는 복원하지 않으므로 앱 재시작 후 시각 비교에는 재촬영이 필요하다.
- 같은 분석 묶음에서 사이즈를 바꾸거나 같은 기준 옷을 다시 측정하면 추가 차감 없이 리포트를 갱신한다. 새 상품·다른 기준 옷은 새 분석이다. 현재 결과 화면에서 비교를 다시 열 수 있다. 별도 히스토리에서 촬영 화면 복원은 지원하지 않는다.

## 기존 배포 앱 보호

- `Info.plist`의 `CoorditCameraComparisonEnabled`는 **false**다. DEBUG 빌드에서만 촬영 진입점을 기본 노출한다. 분석 실행과 저장된 카메라 세션 복원도 이 플래그를 확인한다. 이 브랜치의 입력 화면 간소화는 다음 앱 빌드에 포함되지만 현재 배포 앱과 운영 API는 변경하지 않았다.
- 기존 report 요청/응답 필드를 삭제하거나 필수화하지 않는다. 기존 iOS report 요청에는 신규 필드를 인코딩하지 않는다.
- 첫 카메라 분석은 기존 분석 API에서 1개를 사용한다. 선택적 `cameraComparison: true` 리포트 요청만 새 완료 RPC를 호출하며, 이미 사용한 분석 실타래를 인정해 리포트에서 추가 차감하지 않는다. 리포트가 실패해도 같은 분석으로 재시도하면 추가 차감하지 않는다. 기존 요청은 기존 차감 경로를 사용한다.
- 재측정의 추천·리포트 요청에는 선택적 `comparisonBundleAnalysisId`를 보낸다. 결제된 원본 분석·소유자·상품·기준 의류가 일치할 때만 추가 차감 없이 새 추천 결과를 저장한다. 첫 리포트가 실패한 경우에도 결제된 분석 이력을 인정한다. 재측정 요청 키는 같은 결과 ID로 재생되고 원본 결과를 덮어쓰지 않는다.
- `20261026090400_complete_camera_comparison.sql`은 새 service-role 전용 RPC를 추가한다. 기존 테이블, 컬럼, 함수, RLS와 잔액 데이터를 변경하지 않는다. 이미 결제된 분석에는 리포트만 저장한다. 미결제 분석의 리포트 완료는 결과 저장과 1개 차감을 같은 트랜잭션에서 처리한다. 재시도·동시 요청에는 같은 완료 결과를 반환한다.
- 운영 반영 시 순서는 새 migration → 백엔드 → 검증된 앱이다. 기능을 중단할 때는 앱 플래그를 끄고 추가 RPC는 남겨두면 된다. 기존 RPC를 삭제하거나 되돌릴 필요가 없다. 이 문서는 운영 반영을 수행했다는 의미가 아니다.
- 커밋에는 카메라 비교와 입력 흐름 변경만 포함하며, 같은 작업 폴더의 별도 로그인·결제 보강 변경은 제외했다.

## 검증과 활성화 조건

```sh
cd backend
npm run typecheck
npm run test:camera-comparison
npm run test:report
```

iOS 검증 대상은 `CoorditGarmentMeasurementTests`, `CoorditCameraAnalysisTests`, `CoorditCameraComparisonUITests`와 기존 분석/재시도 UI 시나리오다. 시뮬레이터에서는 DEBUG 전용 합성 사진을 실제 원근 보정 코드에 넣어 측정·자동 등록·비교·리포트·잔액 흐름을 확인한다. 실제 사진 인식 정확도를 증명하는 테스트는 아니다.

릴리스 활성화 전 LiDAR 실기기와 일반 카메라 실기기에서 줄자 실측과 비교해야 한다. 네 부위 각각 평균 절대 오차 1 cm 이하, P95 2 cm 이하를 확인할 때까지 플래그를 false로 유지한다. 평면·빛·촬영 거리·카드 배치가 다른 조건도 검증해야 한다.
